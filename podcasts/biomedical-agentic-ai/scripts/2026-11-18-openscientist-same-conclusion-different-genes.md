# OpenScientist — an open agentic co-scientist whose conclusion replicates across 60 runs while the genes behind it barely overlap

Paper link: https://www.nature.com/articles/s41591-026-04808-6

Preprint link: https://www.medrxiv.org/content/10.64898/2026.03.15.26348338v1

## Script

Most AI co-scientist papers ask whether the agent got the right answer. OpenScientist, out this week in Nature Medicine, is more useful than that. Because the system is fully open, the authors could rerun it dozens of times, swap the model underneath, pull out its memory, and add a shuffled-label control. What those experiments show is where an agent's science actually lives, and it isn't where the architecture diagram puts it.

The work comes from Chris Mungall and Justin Reese's group at Berkeley Lab, the Monarch and knowledge-graph people, with Randall Bateman's Alzheimer's group at Washington University. The design is simple on purpose. OpenScientist is Claude Code in a Docker container with a public library of Agent Skills. Those are plain-text instruction files covering things like transcriptomics or survival analysis. A scientist gives it a question and a dataset. The agent loops ten times: it searches PubMed, writes and runs Python, and records what it found in a JSON file the authors call the knowledge state. Then it writes a report. A run usually costs under ten dollars. The code is Apache-licensed, and there's an air-gapped mode for clinical data.

The case studies are the usual mix. The agent reproduced an unpublished Alzheimer's blood-biomarker analysis from the grant application alone, finding the same top biomarker, percent p-tau 217, that a human team found in SAS. It built a proteomic survival model that ranked third against published aging clocks on the same data. And on a single-cell dataset of neurons with and without tau tangles, it proposed a lysosomal acidification mechanism that a domain expert checked and found sound. The interesting part is what happens around these results.

Start with reproducibility. The supplement reruns the tau-tangle study sixty times, across Claude Opus and two open-weight models, Kimi and GLM, each in online and air-gapped mode. All sixty reports reach the same central conclusion: the proteostasis network is induced and the V-ATPase acidification machinery is upregulated. When two runs both name the same high-confidence gene, they agree on its direction about ninety-nine percent of the time. But when you compare which genes each run lists as significant, the overlap is under eight percent. A key finding in the paper, a regulatory V-ATPase subunit going down while the catalytic subunits go up, shows up in six of ten replicate runs. The other four never mention it. So the conclusion replicates and the evidence cited for it mostly doesn't. If you treat an agent's report as a finding, you need to run it more than once. Whatever appears in only some runs is a lead, not a result.

Next, they removed the memory. The knowledge state is the most distinctive piece of the design, the structured record that lets each iteration build on the last. Withhold it and nothing changes. Findings per run, genes named, and the rate of hitting that key subunit result all stay level. The ablated runs actually found it more often, eight of ten. The transcripts show why. At every reset, the agent reread its own draft report and logs, and those did the same job. The authors draw the honest conclusion. The knowledge state's value is provenance, an iteration-stamped chain of evidence a human can audit. It doesn't make the agent any smarter. For an open-science audience that's a good reason to keep it. It's just a different reason than the one usually given.

Third, the skill file matters more than the model. The tangle data has thousands of cells but only eight donors, so the donor is the real unit of replication, and treating cells as independent samples is the classic pseudoreplication trap. With the default skill, the agent explicitly recognized that in only three of fifteen runs. The authors then rewrote the genomics skill to spell out donor-level pseudobulk and mixed models. Recognition rose to twelve of fifteen, and a complete donor-aware workflow went from zero to nine of fifteen. This lines up with DE-Rigor-Agent from earlier this week. Statistical judgment doesn't come from the model. It comes from instructions someone wrote down. Here those instructions are a markdown file anyone can read, fix, and share.

Now the multiple myeloma case. It's the one I'd read most carefully, and the supplement's run log is where the story is. The agent generated hypotheses from one cohort and was then asked to validate them in an independent Mayo Clinic dataset. On the first validation attempt, all eight hypotheses came back supported. That result, not a planned design, is what led the team to add a negative control: the same dataset with its disease labels shuffled. The agent did reject one of its own pet hypotheses in that final run, and it found much weaker signal in the shuffled data. But the shuffled data still produced 582 differentially expressed genes. The agent never worked out that the labels had been randomized. It flagged a likely normalization problem and recommended reprocessing the data "to recover biological signal." In other words, its response to a true null was to propose more analysis until something turned up. Its supported drug-target hypothesis also landed on BCMA and PSMB5, the targets of drugs already approved for myeloma. The wording changed between versions, too. The March preprint said the agent distinguished true signal from randomized controls. The published abstract says validation came with "attenuated signal in randomized controls," which is the more accurate description.

Two caveats on scope. The preprint's run diagram covers ninety-three development runs, sixty-six of them with data across twenty-nine topics, and says the featured case studies were picked largely on user engagement and on whether experts completed their evaluations. They deserve credit for publishing that diagram, but it's still selection. And the reruns and ablations all used one dataset, the tau-tangle study.

So here's my take. OpenScientist is a credible open baseline, and its biggest contribution is methodological. Because the system is open, its authors could run the experiments that closed systems never report: sixty reruns, a memory ablation, and a shuffled-label control added after the first validation came back clean. Those results set a reasonable bar for anyone using an agent on their own data. Run it several times and trust what holds up across runs. Put your statistical expertise in skill files you can inspect. And never accept "validated" from an agent unless it was also given data where the right answer is no.
