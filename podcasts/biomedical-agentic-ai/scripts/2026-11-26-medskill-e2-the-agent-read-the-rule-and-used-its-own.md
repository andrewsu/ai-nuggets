# MedSkill-E2 — medical agents given the right skill mostly don't use it, and a better one-line description fixes most of that

Paper link: https://arxiv.org/abs/2611.34250

## Script

If you've written a skill for a coding agent, a folder with a short description and a longer instruction file, you've assumed something you may never have tested: if the skill is installed and relevant, the agent will open it and do what it says. Today's paper, from the Shanghai Artificial Intelligence Laboratory with Fudan collaborators, tests that assumption on medical and biomedical tasks, and it mostly fails.

The paper names the failure Enable But Underuse. The skill holds everything needed to solve the task, and the agent still doesn't get there. The design is clean. The same task and the same skill are run under four conditions. No skill at all. The skill installed the normal way, where the agent sees only its name and description and decides for itself whether to open it. A general nudge that a useful resource exists. And what they call operational support: open this file, read it in full, find the procedure that matches, apply every step. That last prompt carries no task-specific knowledge. The gap between natural use and supported use is how much of the skill's value the agent leaves unused.

The tasks are clinical calculations from MedCalc-Bench, data-analysis slices from BixBench, and new tasks on abstract screening, clinical evidence screening, variant functional evidence and enrichment analysis. Nine frontier models run in two harnesses, Claude Code and Codex, for over eleven thousand runs. Without the skill, accuracy is about nineteen percent. With the skill installed normally, thirty-eight. With operational support, eighty-two. Every one of the eighteen model-and-harness pairs leaves a gap.

Don't treat that forty-four-point gap as a measure of how often agents ignore skills in the wild. The benchmark was built to show it. In the last screening step, the authors kept only tasks that a screening model failed on its own and solved with support. So the size of the gap is built in. What's worth your attention is what moves it, and three things stand out.

First, the harness matters about as much as the model. With no skill, or with full support, Claude Code and Codex land within two points of each other. With the skill installed normally, Codex averages fifty percent and Claude Code twenty-six. The cause is simple: under Claude Code, agents opened the skill in twelve percent of runs. Under Codex, sixty-five percent. GPT-5.5 goes from eighteen percent in one harness to forty-three in the other, and how the models rank flips around. Across all eighteen pairs, how often the agent opens the skill predicts its accuracy with a correlation of point nine one. So a leaderboard of skill-equipped agents is a leaderboard of model-harness pairs, and it won't carry over to your setup.

Second, opening a skill doesn't mean following it. Take only the runs where the agent opened the skill in both conditions, and support still lifts accuracy from about sixty-five to eighty-five percent. One trace shows why. The task is a delta gap calculation. The skill says delta gap is the anion gap minus twelve. The agent reads that rule, calls it "unambiguous", then answers with a different, memorized definition. In fairness, that formula is a real one that clinicians use, so part of what's tested here is sticking to a house convention, not just being medically right. That's exactly the risk in specification-driven work, though. Screening criteria, evidence-strength rules and assay eligibility only help if the agent uses the version you gave it, not one it already knows.

Third, and most useful, the fix is cheap. EBU-Evolve takes pairs of runs on the same training task, one natural, one supported, and has Claude Opus 4.8 work out which rule the agent skipped or misapplied. Then it rewrites the skill's description and body, and keeps the rewrite only if it does strictly better on validation tasks. On held-out tasks for four skills, natural-use accuracy rises by thirty-three to fifty-five points. Several groups reach a hundred percent. The rewritten skills carry over: frozen and given to other models, or the same model in the other harness, all twelve transfer setups improve. With the same budget, standard prompt optimizers gained two and eighteen points. The rewrite adds about two hundred tokens per skill.

The ablation is the part I'd act on. Rewriting only the description, the one or two lines the agent always sees, delivers eighty-five percent of the full gain. With the description fixed, opening goes from sixty-two percent to a hundred. The description isn't a summary for humans. It decides whether the skill gets opened at all.

Two caveats. The evolution tests use held-out tasks from the same four skills, so the near-perfect scores show a skill getting better at its own job, not general skill writing. One model regressed on clinical evidence screening, from seventy-seven percent to sixty-two. And the numbers are tied to the specific harness versions they ran. The twelve percent opening rate under Claude Code describes one release, not a permanent property of that harness.

My take: as biomedical groups package curation rules, pipelines and evidence standards as skills for agents, this paper changes what "we gave it a skill" means. Three practical rules follow. Write the description as a trigger: state when the skill applies and that its rules override what the model already knows. Test skills in the harness you actually deploy, because results don't carry over between harnesses. And in your evals, run the supported condition alongside the natural one. The difference between them shows how much of your skill the agent isn't using, and it's a better quality check for a skill than any amount of reading it over.
