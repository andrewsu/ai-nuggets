# Orbit — provenance is where you run, not how careful you are

Paper link: https://www.biorxiv.org/content/10.64898/2026.10.26.761864v1

## Script

Today's paper comes from the Galaxy project — Nekrutenko and Kosakovsky Pond's groups, which is to say the people who have spent twenty years building public bioinformatics infrastructure. It's called "Verifiable Agentic Science on Public Infrastructure," and it opens with an experiment I want to describe carefully, because the obvious reading of it is wrong.

They took a published bacterial RNA-seq study — a Bacillus cereus paper on how dietary glucose regulates enterotoxin expression — and asked thirty independent coding agents to design a replication plan. Ten running Claude Opus, ten running Codex, ten running Gemini. The agents splintered. Twenty-nine of the thirty produced a plan that differed from the published workflow, and the thirty plans collapsed into eighteen distinct pipelines, eleven of which differ in ways that actually change the gene counts and the p-values.

Now, the easy conclusion is that agents are unreliable. But look at where the forks are. Twelve agents picked one reference assembly, seventeen picked another. Twelve pooled all nineteen libraries into the differential expression model, eighteen used only the five focal samples. Those are precisely the two things the original paper never stated. The methods text reported locus tags from a related strain without naming the assembly, and it never said whether the model was fitted on all the libraries or just the relevant ones. The agents didn't invent the ambiguity. They inherited it, and because you can run thirty of them, they made it legible in a way that one careful postdoc reading the methods section never would.

And the fork wasn't cosmetic. All three executed runs recovered the paper's headline result. But the agents that aligned to the related-strain assembly missed cytotoxin K entirely — not because it isn't expressed, but because that assembly doesn't contain the locus. Align to the actual sequenced isolate and cytotoxin K is transcribed across every library. Same data, same headline, different toxin repertoire. The three local runs also left behind twenty-six unversioned glue scripts, over twelve hundred lines of non-portable code that exists nowhere now.

So the proposal. Instead of building another specialized research agent, connect ordinary command-line agents to Galaxy — through an MCP server and a set of skills — so that execution happens on public infrastructure. Every tool version, every parameter, every intermediate dataset lands in a shareable history and a workflow graph, on free national supercomputing resources, without the agent needing cluster credentials.

The thing I find genuinely clarifying here is the argument for why this has to be infrastructure rather than instruction. They also built a desktop application called Orbit, and their reasoning is blunt: prompt-level instructions can be ignored, and nothing in a skill file stops an agent from quietly falling back to a local shell command when a step fails. Galaxy gives you a server-side record of typed tool invocations that the agent cannot edit. So the harness can check against Galaxy whether a job actually finished before letting the agent mark a step complete. Provenance stops being a discipline you maintain and becomes a property of where the computation ran.

Then they turn it on seven real analyses, and the best result is the one with the sharpest irony. They tried to reproduce the spatial transcriptomics demo from Paper2Agent — a recent system whose whole pitch is wrapping published code into agents for reproducibility. The demo imputes expression of a smooth muscle marker across mouse cortex cells, and its methods and data availability statement cite a five-thousand-six-hundred-cell reference atlas. What it actually ran on was a ninety-six kilobyte, one-thousand-cell tutorial subset bundled in the software repository. Orbit reproduced the tutorial version to floating-point precision, then ran the identical workflow against the full cited reference. Correlation with measured ground truth went from about zero-point-zero-nine to zero-point-two-six — roughly tripled — and the predicted localization moved from a diffuse ventral smear to the dorsal pial vasculature, which is where that marker actually lives. Twenty-seven of thirty-three genes improved. A reproducibility demonstration was not reproducing what its own text said it was, and the only reason anybody noticed is that someone re-ran it somewhere the inputs were recorded.

The other reanalyses find the same genre of thing: a fungal time-course where the authors fitted one pooled thirty-sample model rather than the pairwise contrasts the prose implies, plus a decommissioned web service and two manual web steps replaced with containerized tools; a mosquito chromatin study whose headline peak counts turn out to be unmerged per-replicate rows.

Two things keep this honest. The first is a sentence the authors write themselves, and it's the most important one in the paper: these guarantees apply to the record, not to the science. Orbit does not make an agent's analytical choices correct; it makes what the agent did checkable. That's the exact mirror of yesterday's episode, where VariantAgent produced right answers over invalid traces. Here you get a valid trace with no promise the answer is right. Both halves have to hold, and nobody has both yet. The second is that they report where it underdelivers — the epidemic-dating module matched the reference Bayesian estimates on only about sixty percent of cohorts, and agent-level metadata like which model submitted which job still lives in local session logs rather than being stamped onto the Galaxy jobs, which is a real gap in a paper about provenance.

Where this lands for me is the last paragraph of the discussion, which is making a much larger claim than the title suggests. If an agent executes a study on public infrastructure, they argue, the primary scientific product stops being the prose manuscript and becomes the archived crate of inputs, workflows, container digests and results. The paper is then a rendering of that object, and you could generate it in whatever format a reader wants. I'm not sure that's where publishing actually goes. But it's the first version of that argument I've seen where the infrastructure to test it already exists, has existed for two decades, and is free.
