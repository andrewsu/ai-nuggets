# Murmurent — an agentic operating system for an academic research centre

Paper link: https://www.biorxiv.org/content/10.64898/2026.09.24.753565v1

## Script

Almost every agentic AI system we cover on this show is vertically integrated around a single scientific endpoint. Find a drug for this disease. Run this assay loop. Answer this literature question. That shape came out of industrial pipelines, where there's one funnel and one success criterion, and AI gets inserted as an accelerant at one stage. A preprint posted this week from Western University argues that the shape is wrong for academia, and builds the alternative. The system is called Murmurent, and it's best described as the layer underneath agentic AI — the identities, permissions, shared memory and data-governance rules that let a whole building's worth of agents coexist without anyone getting hurt. It's open source, Apache licensed, and it runs on top of Claude Code.

The central design choice is in the vocabulary. The authors reject orchestration — one controller that understands every project well enough to micromanage it — because in a university no such controller exists. Each lab owns its data, sets its own success criteria, answers to its own funder. What they propose instead is choreography. A choreography starts with a hard question, and every group answers it with an approach of their own choosing. What the system negotiates is not the answer but the terms of comparison: which quantities get reported, in what units, how uncertainty is expressed, and, critically, what serves as a control. That gets settled before anybody builds anything. Nobody declares a winner. The question is what holds the groups together.

The memory design is where I'd point a computational biologist first, because it contains a pointed argument against how most of us do retrieval. Murmurent splits memory into three tiers, and the middle one — the lab's accumulated qualitative knowledge, observations, decisions, negative results, the reasoning behind a methodological choice — is stored as plain markdown under version control, each entry carrying mandatory front matter: author, date, project, sensitivity tier, sources. Retrieval is filtering on that front matter plus keyword scoring of the body. Deliberately not a vector index. Their case against the index is that it's a derived cache, regenerated whenever the corpus or the embedding model changes, so it carries no history of what was known when, and a retrieval can't be reproduced once you rebuild it. With files under version control, a person can open the exact same file the agent read, see who recorded it under what sensitivity, fix it in place, and recover the correction from the history. For anyone who cares about provenance, that trade is worth thinking about hard.

The third commitment is that rules get applied when the agent acts, rather than asked of it. Hooks fire on every tool call and refuse to delete or overwrite anything in the raw-data tree, whatever the model reasoned or however the request was phrased. The principle the authors state is that the agent itself is untrusted and its behavior has to be verified rather than assumed. They're equally plain that this is incomplete: the hooks stop an agent from uploading sensitive data, but they do not stop a script the agent wrote from doing it.

Now, the part that makes this preprint worth your time. They ran a real choreography: four groups, four independent approaches to inhibiting Pin1, a genuinely nasty target whose catalytic site is a shallow solvent-exposed groove. The shared control, agreed in advance, was simple — rank the known Pin1 binders above decoys matched to them on size, greasiness and charge. The covalent approach first scored an area under the curve of point eight one five, which looks like a real result. Then the adversarial review agent objected: decoys matched only on whole-molecule properties can be told apart from real binders by chemical scaffold alone, so that number is measuring scaffold recognition, not binding. Two corrections followed. Scoring each molecule in its bound, post-reaction form dropped it to point seven one eight. Requiring every decoy to carry the same reactive chemistry as the binder it's matched to dropped it to point five three seven — chance. And because class-matching left only two chemotypes against the six the project had pre-committed to requiring, the final entry records not how badly the ranking works, but that it was never shown to work at all.

They then pushed on the instrument itself. Given structures where the true ligand pose is known, the docking program's top-scored pose is correct no more often than one picked at random, while the correct pose is among the nine it proposes about forty-two percent of the time. The search finds the answer and the scoring can't recognize it. Sulfopin — a covalent Pin1 binder confirmed crystallographically — is outscored by fifty of eighty property-matched decoys.

So the system's principal output was a refusal. All four approaches produced shortlists; the shared control certified none of them; nothing was synthesized. I think that's the strongest thing in the paper, and the authors know it. Four plausible ranked lists, developed in parallel by four competent people, would have gone to the bench. There's a second artifact I'd steal outright: a project file cataloguing the twenty-one mistakes this project actually made, read at the start of any session that writes code. Almost all of them have the same shape — code pulled a value out of a table by position or by name or by default, without checking that the table's shape matched the assumption. The wrong value was as plausible as the right one, so nothing crashed and no test fired. Nine of the twenty-one reached a result and forced a claim to be withdrawn. Only three were caught by an automated check. The authors read that as an argument for writing more checks, not for auditing harder, which is the correct lesson and an uncomfortable one.
