# BioChirp — deterministic retrieval that stops AI agents from silently gutting biomedical databases

Paper link: https://www.biorxiv.org/content/10.64898/2026.04.25.720782v2

## Script

Here is an uncomfortable question for anyone wiring an AI agent onto a curated biomedical database: when the agent hands you back a clean, confident answer, how much of the evidence did it silently leave on the floor? A preprint out of a group at IIIT-Delhi, describing a system called BioChirp, spends most of its effort just measuring that gap — and the number that falls out is the kind that should change how you use these tools.

Here is the demonstration that sticks with you. They asked for all the molecular targets associated with chronic myeloid leukemia in Open Targets. The most reliable agent they tested — a current frontier model connected through the official Model Context Protocol server — returned ninety-nine targets. The real answer in the database was four thousand four hundred and seventy-three. So the agent recovered about two percent of the evidence, twice, with no error, no warning, no hint that anything was missing. It just stopped. That is the trap: a well-formed tool call and a truncated result set look identical from the outside.

And it is not just truncation. They document two other failure modes that all share the same signature of silent loss. The first is terminology. Ask for the targets of Gleevec instead of imatinib, or use an old gene symbol, and the query can come back empty — not wrong, just empty, because the agent preserved your wording in an exact-match filter that the database never stored. The second is irreproducibility. Run the identical question five times and you get different result sets, because a language model is somewhere in the loop generating the query or deciding when to stop. They even ran a control where language models answered biomedical association questions from their own internal knowledge, and those models recovered zero to two percent of what the databases actually contain — while agreeing with each other far more than with the database. In other words, they converge on the same small, well-trodden slice of biology and quietly ignore the rest.

So the diagnosis is that final-answer correctness — the thing everybody benchmarks — hides retrieval failure completely. You have to measure completeness and reproducibility as separate axes, and almost nobody does.

BioChirp's fix is a design principle worth internalizing: interpretation-execution separation. Use the language model only for the parts that genuinely require language and biomedical judgment — figuring out what the question is asking, which fields to filter on, and mapping the user's messy terms onto the database's canonical vocabulary. And then, the moment that specification is fixed, the language model is done. It never touches retrieval. A deterministic planner takes over — it treats the database schema as a graph, tables as nodes and foreign keys as edges, and builds a Steiner tree connecting exactly the tables the question needs. An executor then pulls every matching record within its limits. Same specification, same database snapshot, same answer, every single time. Reproducible, and — just as importantly — auditable, because you can see the resolved terms and the join path.

A couple of the engineering choices are smart in ways that generalize. Instead of one model translating the question, two independent models propose the field mapping, and when they disagree, an orchestrator arbitrates — which fixed essentially every disagreement in their tests, and sometimes produced the right answer when neither model had it alone. But the authors are refreshingly honest about the failure this cannot catch: when both models confidently agree on the same wrong mapping, nothing flags it. And for synonym resolution, they show there is no magic fixed cutoff — no single number of candidates, no single similarity threshold works across diseases, drugs, and genes, because a term might have fourteen synonyms or ninety-six. So they let the retrieval depth adapt per query, then have a cheap language model prune the false matches.

Does it actually work? Across a benchmark of nine hundred and ten questions drawn from expert-written biomedical questions and spanning ten relational databases, BioChirp pulled at least one real database record eighty-five percent of the time and produced a fully correct answer fifty-one percent of the time. The agentic natural-language-to-SQL baseline managed forty-five percent and seventeen percent. On reproducibility, BioChirp returned identical result sets across repeated runs; the language-model systems drifted all over the place.

Why this matters for this audience specifically. This is the plumbing problem for agentic science — the layer between an autonomous agent and the curated knowledge in Open Targets, ClinVar, Reactome, STRING, and the rest. And they built it to compose: it is deployed as a live public service with a Model Context Protocol gateway, so an external agent can chain BioChirp calls across databases — start from a gene in STRING, carry its interactors into Reactome for pathways, hand those into a toxicogenomics database for associated chemicals — with each retrieval step complete and reproducible even if the overall reasoning is not.

The honest caveat is right there in the architecture: determinism only protects everything downstream of interpretation. A synonym missed or a field mapped wrong at the top still propagates, and no amount of deterministic execution downstream can recover it. Interpretation recall is the ceiling. But that is exactly the right place to concentrate the hard problem — and a far better failure mode than an agent that looks like it answered and gave you two percent of the truth.
