# MRCAT — a Mendelian randomization agent team, and six flipped allele signs that turned a null result into a causal claim

Paper link: https://www.medrxiv.org/content/10.64898/2026.11.16.26368234v1

## Script

When an analysis agent crashes, nobody gets hurt. The failure that matters is the agent that finishes and hands you a confident answer that's wrong. Today's paper makes that point unusually concretely, in the field where it probably matters most. It's MRCAT, a multi-agent system for Mendelian randomization, posted to medRxiv on Thursday by Can Yang's group at the Hong Kong University of Science and Technology. That's the statistics group behind several widely used MR methods, so they know where the bodies are buried.

A quick refresher on why this field is a special risk. Mendelian randomization uses genetic variants as natural experiments. If variants that raise your BMI also raise your diabetes risk, in proportion, that's evidence BMI causes diabetes. With public GWAS summary statistics, anyone can run one in an afternoon, which is exactly why the literature is already flooded with low-quality MR papers. Now hand that afternoon to an agent and the throughput goes up by orders of magnitude. So the question isn't whether an agent can produce an MR estimate. It's whether the estimate means anything.

MRCAT's answer is architectural. A manager coordinates three agents, one to search for literature and GWAS data, one to run the analysis and one to write the report. The real substance is in twenty-six MR-specific skills. Each one wraps an established implementation with explicit decision rules, quality checks and, importantly, stopping conditions. A planner orders the steps by their dependencies, so LD clumping and allele harmonization have to happen before estimation. A reviewer looks at failures and decides whether to fix a step, redo something upstream, or stop because the data can't support the analysis. On the reporting side, a writer drafts against the STROBE-MR reporting guideline and a judge sends it back if the words claim more causality than the numbers support.

The benchmark is thirty natural-language queries. Twenty-six can be executed, and four are traps, like asking for a method when the required sample-size information doesn't exist. Every system ran on the same model backbone, DeepSeek V4 Pro. That includes the system labeled Claude Code, so read that comparison as a test of the Claude Code harness, not of Claude. Claude Code and MRCAT both produced an estimate for all twenty-six. But only seventeen of Claude Code's runs passed all nine procedural checks, against all twenty-six for MRCAT. Biomni managed eleven and BioMedAgent four. On the four traps, MRCAT stopped or adapted honestly every time. Claude Code did it twice, and the other two once each.

The numbers that should stick with you come from the expert-curated cases. On the BMI and type 2 diabetes tutorial analysis, Biomni mislabeled the effect alleles, skipped LD clumping, and fit more than seven thousand variants. It got the effect in the opposite direction, with a p-value around ten to the minus seventy-five, and its report called that strong evidence that BMI protects against diabetes. Then come six negative controls, exposure and outcome pairs where expert analyses found no causal effect, with the trait names hidden. Across fifty-three method-specific results that should have been non-significant, Claude Code returned seventeen significant ones and Biomni fourteen. MRCAT returned two, both borderline and both close to the expert values. In the cleanest example, the authors traced Claude Code's false positive to six palindromic SNPs. Those are variants where the two alleles look the same on either strand, so you can't orient them by letters alone. The agent reversed their outcome signs during harmonization. Fix those six signs and all nine of its significant results become non-significant. Its final report on another of these pairs read: "Both methods indicate a positive causal effect."

That one line is the paper's most useful lesson, and the authors state it themselves. Agreement across several MR methods looks like triangulation. But if every method is fed the same mis-harmonized data, agreement isn't independent confirmation. It's the same error counted five times. A human reviewer seeing IVW, weighted median and MR-Egger all agree would relax. That's exactly the wrong moment to relax.

Now, how much of MRCAT's perfect scorecard should you believe? Less than the headline, for three reasons. First, the nine procedural checks were written by the same people who wrote the skills, and the skills enforce those checks. Twenty-six out of twenty-six partly measures whether the system obeys its own checklist. Claude Code's average was eight and a half out of nine, so the gap is real but narrower than "seventeen versus twenty-six" sounds. Second, MR-APSS, the method in the showcase reproduction, comes from this lab, so that's home turf. Third, an LLM judge scored the benchmark, and there are only six negative controls. The authors flag the judge problem and call for human adjudication with inter-rater agreement, which is the right next step.

None of that undercuts the take, though. This fits a pattern we keep seeing on this show. On Wednesday, OpenScientist's myeloma analysis looked validated until someone added a shuffled-label control. Yesterday, DeepQuest's novelty verdict turned out to depend on how much literature the auditor read. In each case, a generic agent is fluent enough to produce a finished-looking analysis and not expert enough to know which step is load-bearing. MRCAT's reliability doesn't come from a smarter model, since everyone had the same one. It comes from a field's tacit knowledge, written down as executable skills with stop conditions: palindromic SNPs need special handling, and clumping comes before estimation. That skill library is the artifact worth stealing. It's on GitHub under a BSD license, and the pattern should transfer to any analysis with a well-defined way to go wrong, like colocalization, differential expression or survival analysis.

One last thought for anyone running agent benchmarks. Test the negative controls. An agent that finds every positive is easy to build. The one worth trusting is the agent that, given nothing, reports nothing.
