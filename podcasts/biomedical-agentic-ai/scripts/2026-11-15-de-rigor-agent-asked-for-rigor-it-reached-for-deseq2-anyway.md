# DE-Rigor-Agent — an RNA-seq agent that has to rule out each differential expression method before it runs one, because asking for rigor doesn't change what agents pick

Paper link: https://www.biorxiv.org/content/10.64898/2026.11.09.765522v1

## Script

Here's a small experiment that says a lot about how coding agents do science. Give an agent a table of RNA-seq counts and ask it to find the differentially expressed genes. It picks DESeq2. Now add one sentence to the prompt: consider the assumptions of the different methods and the characteristics of the data, and choose a statistically rigorous one. It still picks DESeq2, or edgeR, on almost every dataset, including datasets built specifically to break those methods.

That's the baseline result in a new preprint called DE-Rigor-Agent, from Jingyi Jessica Li's biostatistics group at Fred Hutch. The group is a fitting source. In 2022 they argued in Genome Biology that the most popular differential expression tools can give exaggerated false positives on large human population samples. Now they're asking whether agents inherit the same habits, and how you'd stop that.

To answer it you need ground truth, so they simulated it. They built 140 bulk RNA-seq datasets calibrated to a real airway study, each with 400 known differentially expressed genes out of 2,000, across 14 scenarios: very small samples, excess zeros, a few extreme high-expression outliers, input that was already normalized, and a batch effect partly confounded with the condition. Then they ran all six candidate methods on every dataset, whether or not the method suited the data, so you can see what a wrong choice costs.

The cost is real. With high-expression outliers, edgeR's empirical false discovery rate, at a nominal five percent, ran between sixty-one and seventy-nine percent. Most of its calls were false. DESeq2 drifted up to about a third. Limma-voom stayed calibrated on the same data. Under the confounded batch effect, the two nonparametric methods, Wilcoxon and NOISeq, which can't adjust for covariates, inflated instead. No method is safe everywhere, which is the whole point.

Now the agents. All three used the same underlying model at the same reasoning effort and got the same data and the same list of six methods. Plain Codex chose DESeq2 for nearly everything and rarely said why it skipped the others. The guided version, with the extra rigor sentence, sometimes rejected one method or another, but its choices barely changed between clean data, zero-inflated data and outlier-ridden data. Neither one ever excluded the negative-binomial methods when the data broke the negative-binomial assumption. Interestingly, both did switch to plain limma when handed normalized, non-integer values. So the agents react to cues they can see on the surface. They don't run the diagnostic that would expose a violation they can't see.

DE-Rigor-Agent's fix is structural rather than clever. The workflow is a fixed three-stage graph: standardize the inputs, filter the methods, then execute. The filtering stage is the heart of it. Each method has a method card, a short natural-language spec of its distributional assumptions, the input it needs and the designs it supports, along with a few filtering principles, such as Wilcoxon having little power at three samples per group. The agent writes and runs its own diagnostics against those cards and must document a keep-or-reject decision with evidence for every method. The user can approve or push back but can't override the criteria. Then every surviving method runs, each in its own subagent working from an expert-written code template, and the report shows all of them.

Two parts of that design matter more than the agent does. First, the method is chosen before any results exist, which removes the oldest temptation in the field: running everything and reporting whichever method gives the nicest gene list. Second, the expertise lives in an editable artifact, not in the model. A statistician can read the method cards, argue with them and change them without touching code, and the cards, prompts and code are all on GitHub.

On the simulations, its exclusions largely matched the planted problems. It dropped DESeq2 and edgeR under outliers and zero inflation, dropped Wilcoxon at tiny sample sizes but kept it at larger ones, and dropped the covariate-blind methods when batch adjustment was needed. It was mostly stable, with the same decision in at least eight of ten replicates for 77 of 84 scenario-method pairs. The cost went from about half a cent per dataset to just under two cents.

Now the caveats, and they're specific. The instability sits exactly where it hurts. With mild outliers at twelve samples per group, it kept edgeR and DESeq2 in four of ten runs, and that's the setting where edgeR's false discovery rate was sixty-one percent. When the evidence is faint, the diagnostics can miss it. More fundamentally, the same team wrote the filtering criteria and designed the failure modes they planted, so the benchmark mostly shows that an agent will reliably apply rules experts wrote to problems those experts anticipated. That's worth having, but the harder test is real data, where violations are messy, overlapping and unlabeled, and there's no real-data evaluation here yet.

Still, the lesson travels well beyond RNA-seq. Yesterday's episode was about logging what an agent actually did. This one sits a step earlier, at the choice of what to do. An agent's default isn't neutral. It's the most popular tool in its training data, and a sentence asking for rigor doesn't change it. What changes it is putting the expert knowledge where the agent has to check against it, before it sees any results, and putting it somewhere a human can audit. Any analysis where the right statistical method depends on the data needs a method-card layer like this, and plenty of agent skill libraries today simply hand the model a DESeq2 wrapper.
