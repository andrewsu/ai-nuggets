# MDClaw — an execution graph that catches agent-run molecular dynamics passing every check after skipping equilibration

Paper link: https://www.biorxiv.org/content/10.64898/2026.11.09.765490v1

## Script

Yesterday's episode ended on the idea that reproducibility certifies the numbers, not the inference. Today's paper makes a quieter point that comes first: a correct-looking output doesn't certify the process that produced it either. It's MDClaw, a harness for running molecular dynamics simulations with coding agents, from Yasuhiro Matsunaga's group at the RIKEN Center for Computational Science in Kobe. The toolkit itself has been on GitHub for a few months. What's new in this preprint is the benchmark and, more importantly, one ablation.

The motivation is simple. Agents now produce hypotheses about mutations, binding and stability faster than anyone can test them, and many of those hypotheses are stated at the atomic level, where a simulation can test them. But the hard part of molecular dynamics isn't the integrator. It's setup: choosing protonation states, force-field parameters, solvent and membrane, then running minimization, equilibration and production in the right order from the right files. Existing MD agents let the language model decide the order of stages and pass files between them, so the only record of what happened is the agent's own log. That's the same agent whose work you're trying to check.

MDClaw takes the record away from the model. It gives the agent a hundred command-line tools and fourteen short protocol documents, and every tool writes its calculation as a node in a directed acyclic graph that lives on disk, outside the model's context. The graph also constrains execution. A stage runs only if its parent completed, the transition is allowed, its inputs come from recorded ancestors, and its settings match what was declared. So a failed minimization can't feed an equilibration, a stray file can't enter the pipeline, and an equilibration declared at three hundred ten kelvin gets rejected if it's configured at three hundred. When a call is refused, the tool says why and the agent branches from the last valid node instead of starting over.

To test it they built MDDataBench from the Molecular Dynamics Data Bank federation, a set of community repositories holding about thirty-five thousand deposited simulations. That's a nice open-data move, because it means agents are graded against simulations that neither the agent nor the benchmark authors produced. There are thirty-one held-out test systems: soluble proteins, complexes, antibodies, nucleic acids and one sodium channel in a lipid bilayer. Grading reads only the files, with twelve checks on the prepared system and eight on the trajectory, including fluctuation profiles and radius of gyration against the reference. The agent's summary isn't scored at all.

Four open-weight models ran each task three times. With just the simulation software in a container, twenty-one of three hundred seventy-two runs passed, and nearly three quarters never produced a trajectory at all. With MDClaw's tools, the fraction of systems passing all three runs rose to between eighty-one and ninety-four percent, and adding the protocol documents pushed it to ninety to a hundred. The design lesson is in that split. The tools did most of the work, and over development the gap between tools alone and tools plus skills shrank from twenty-eight model-task pairs to eight, as expert knowledge moved out of prose the agent might not read and into checks the tool always enforces. MDCrow, an existing dedicated MD agent, usually did produce a trajectory, but over sixty percent of its runs failed the chain, sequence and composition checks. It was simulating a different system from the one it was asked for.

Now the ablation, which is the reason to read the paper. They rebuilt MDClaw without the graph. The chemistry and the validating checks were unchanged, but the agent now carried files and settings from stage to stage itself. The benchmark barely noticed. Systems passing all three runs went from a hundred eight of a hundred twenty model-system pairs to a hundred three, which isn't a significant difference. But they had also logged content hashes for every file each tool touched, so they could reconstruct what had actually happened. Among three hundred thirty-four successful runs, eleven were wrong. In six, equilibration started from the raw topology build rather than the minimized structure. In two more, production did too, so the scored trajectory had neither minimization nor equilibration behind it. In one example, minimization and equilibration both ran and their outputs were simply never used. In the other three, the agent had swapped in its own files, so the structure it simulated wasn't the one it had prepared. All eleven passed every output check. With the graph, none of three hundred forty-three successful runs had such an error.

Eleven in three hundred thirty-four is about three percent, and you could read that as reassuring. I'd read it the other way. Those errors were only detectable because a reference simulation existed and the authors logged file hashes on purpose. In real research there is no reference, and a short unequilibrated trajectory can look perfectly plausible. The authors put it plainly: without a reference, only a record of the process can reveal these errors, and the record has to be written by the tools, not the agent.

They close by pointing MDClaw at real questions. Human scientists asked about Abl kinase substrates, and eighteen microseconds of simulation reproduced the ordering seen in enzyme kinetics. They also gave it five hypotheses from the Biomni AI scientist about a Neurospora mutation. The free-energy estimate for the key substitution landed inside the range Biomni predicted, but within the time limit only one of the five hypotheses was even partially supported. That's an honest result, and it's what you'd expect from MD's sampling limits.

They're also candid about limitations. The graph isn't tamper-proof, since an agent with write access could edit it, so records should live where the agent can't write. And it can't tell you whether a force field or starting model suits the question.

Here's the take. The field keeps building benchmarks that grade final artifacts and then treating a high pass rate as a license to deploy. This paper shows the pass rate can be indifferent to whether the steps happened at all. If you're running agents in any multistage pipeline, whether that's simulation, variant calling or knowledge-graph builds, two habits follow. Put the domain knowledge into checks in the tools, not paragraphs in the prompt. And make lineage a property of execution, so no file enters a stage unless the record says where it came from. There's an open-science bonus too: the same graph exports a Methods draft and a deposition bundle, so agent-run simulations could flow back into the shared databank with their provenance attached.
