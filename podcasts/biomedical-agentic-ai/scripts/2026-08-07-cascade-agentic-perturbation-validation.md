# CASCADE — an agentic perturbation predictor built to test whether an MCP tool call is actually true, not just plausible

Paper link: https://arxiv.org/abs/2608.05359

## Script

Today's paper is a quiet, almost stubbornly honest piece of work, and I want to talk about it precisely because it refuses to oversell itself. It's called CASCADE, and on the surface it's yet another agentic biomedical tool: a LangGraph-orchestrated workflow, wrapped in the Model Context Protocol so that a language-model agent can call it in plain English, that predicts the downstream transcriptional consequences of perturbing a gene. You ask it, in effect, "if I knock down this gene, which other genes go up and which go down," and it answers by propagating a signal through pre-computed regulatory networks — ARACNe networks, which are basically data-driven maps of which transcription factors control which target genes, one map per tumor type. It's the work of a single independent researcher, extending his own earlier system called RegNetAgents.

Now, if the story stopped there, this would be a routine entry in the pile of "I wired an LLM to a bioinformatics tool" preprints. What makes it worth five minutes is the question the author actually asks, which is not "is my tool cool" but "when an agent calls this tool and repeats its answer to a user, is that answer true?"

Here's the subtle point, and it's one I think every agentic-AI builder should sit with. The usual way people validate a network-propagation tool is membership validation: you check whether the genes it predicted are already known cancer genes. But that only asks whether the prediction is plausible — whether it's in the right neighborhood. It never checks the specific claim the tool surfaces, which is directional: this gene goes up, that one goes down. And when you expose that tool as an MCP function call, the agent inherits exactly that gap. It will confidently report a direction of change that nobody ever actually checked against reality. Plausible is not the same as true, and the tool call papers over the difference.

So CASCADE's real contribution isn't the predictor — it's a validation methodology that tests the directional claim itself. And the trick is clever: you can't easily run a knockdown experiment for every gene, so instead the author uses a natural experiment already sitting in patient data. Copy-number amplification — where a tumor has extra copies of a gene — is treated as roughly the dosage inverse of a knockdown. If knocking a gene down should push its targets one way, then amplifying it should push them the other way. So you take the tool's predicted directions, flip them, and ask whether real tumors with the gene amplified actually show those expression differences versus tumors without amplification.

For MYC, the classic oncogene, the result is genuinely strong. Ninety percent directional concordance in breast cancer, holding up across colon and stomach tumors, surviving a molecular-subtype control, and — the part I trust most — replicating at eighty-seven percent in METABRIC, a completely independent breast-cancer cohort with different patients, different country, different measurement technology. Permutation baselines sit right at the fifty-percent coin-flip line, so this isn't an artifact of gene-set structure.

And then comes the honesty, which is the whole reason I picked this. First: when the author benchmarks CASCADE against a plain curated list of known MYC targets, the gap is one to four percentage points, in both directions, not statistically significant. In other words, the agentic tool matches expert-curated public knowledge — it does not beat it. He says so flatly. Second: the validation is gene-specific, not universal. Proliferation-machinery genes — the cell-cycle engine — validate cleanly. But lineage-identity transcription factors, the ones that define what kind of cell you are, fail across the board, sometimes landing near zero concordance. There's even a cyclin gene that fails in the exact tumor type where its two near-identical paralogs succeed, which breaks any clean rule you'd want to draw. Third, and most relevant to agentic AI specifically: the step where the agent turns a natural-language request into the right tool-call parameters is itself only seventy-one percent accurate with a small local model, eighty-six with a larger one — and there's a failure mode where the model confidently picks the wrong perturbation type that a server-side fix can't even catch, because the bug only triggers when a field is left blank, and the model always fills it in wrong instead.

So stack those up. The tool can be right but no better than a lookup table. The tool can be right for one gene class and wrong for another. And the agent standing in front of the tool can call it incorrectly before the tool ever runs. Three independent places for a confident, wrong answer to be born — and standard membership validation catches exactly none of them.

That's the take. This is a template, not a triumph: a concrete, patient-data-grounded way to ask whether the claim your agent surfaces is one you've actually checked against reality. In a field racing to wrap every model in tool calls, that's the discipline we're mostly skipping.
