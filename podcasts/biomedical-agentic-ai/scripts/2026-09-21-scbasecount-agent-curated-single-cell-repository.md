# scBaseCount — an AI agent curates the Sequence Read Archive into 502 million uniformly processed cells

Paper link: https://doi.org/10.1016/j.cell.2026.08.025
Preprint: https://www.biorxiv.org/content/10.1101/2025.02.27.640494v3
Code: https://github.com/ArcInstitute/SRAgent
Data: https://github.com/ArcInstitute/arc-virtual-cell-atlas

## Script

Today's pick went up in Cell on Thursday, out of Arc Institute. scBaseCount is a single-cell RNA sequencing repository holding a little over five hundred and two million cells across twenty-seven organisms and seventy-five tissues, which makes it the largest public collection of single-cell expression data by a wide margin — the Chan Zuckerberg cell-by-gene atlas has a hundred and twenty-three million cells, the Human Cell Atlas sixty-five million. But the size is not the interesting part. The interesting part is that this is, as far as I can tell, the first large biological data repository curated end to end by an AI agent.

Start with the problem, because anyone who works with public data will recognize it instantly. The Sequence Read Archive holds raw reads for essentially every published single-cell experiment, and it is almost unusable in bulk, because the metadata is whatever the submitter felt like typing. Which organism, which tissue, which chemistry, cells or nuclei, what disease — all free text, inconsistently populated, frequently absent. So the curated atlases took the other road: ask investigators to contribute datasets and annotate them by hand, which buys expert-quality labels on a small, self-selected slice of what exists. Both roads were blocked for the same reason. Reading two hundred thousand submission records and deciding what each one contains is a judgment task, and judgment tasks used to mean people. Arc's move was to notice that this is exactly the shape of task an agent is now cheap enough to run two hundred thousand times.

The agent is called SRAgent, and the architecture deserves a moment because they tell you what didn't work. The first instinct was one reason-and-act agent holding all the tools — the Entrez utilities, SRA BigQuery, scraping NCBI pages, read-level tools for pulling the actual files. Too many tools, too long a task, for a single agent. So they decomposed it into a supervisor-and-worker hierarchy: a find-datasets agent pulls candidates from eSearch, the supervisor hands each one to a metadata agent, and that agent calls sub-agents for Entrez, for fetching, for BigQuery, for tissue ontology — the Entrez agent having sub-agents of its own, one per tool. The efficiency argument generalizes: only a sub-agent's final result travels back up, so nobody's context ever gets big.

The ontology work is where I'd point a skeptic, because it's where agentic curation could most easily go wrong and doesn't. To assign tissues, they turn the text of the Uberon ontology into a vector database, have the agent semantic-search it with a free-text tissue description, then walk the neighboring terms in the hierarchy and call the Ontology Lookup Service when it needs more validation. Diseases get the same treatment against MONDO. And critically: when the metadata genuinely cannot be narrowed to one term, the agent keeps several rather than choosing. That is the correct behavior, and it is not the default behavior of a language model asked to emit an ontology identifier.

So how good are the labels? Tissue assignments mostly agree with the Chan Zuckerberg atlas's expert annotations on the overlapping datasets, and on every shared dataset the atlas had flagged as diseased, the agent also identified the disease under study. Then it went further: in datasets the Chan Zuckerberg atlas marks as normal, the agent sometimes flagged a disease context anyway, and when the authors checked by hand, the agent was right. Those are exactly the small, scattered studies of rare conditions that never make it into a curated atlas.

A repository only matters if something downstream gets better, and here the paper earns its place. First, uniform reprocessing — every dataset realigned with the same pipeline and reference, exonic and intronic reads both retained — measurably flattens batch effects. Scoring how strongly each metadata variable drives clustering, sample identity in scBaseCount shapes the data about as much as tissue does, which is roughly what you'd hope for. In the Chan Zuckerberg atlas, sample identity dominates; study-specific processing was leaving a fingerprint. The cells-versus-nuclei split is the clean illustration: nuclei are conventionally counted with intronic reads and cells without, and keeping both counts makes the artifact vanish.

Second, and this is the number to keep: they trained the same hundred-million-parameter cell embedding model twice, once on scBaseCount and once on the Chan Zuckerberg atlas, human cells only in both, so raw size and species breadth aren't doing the work. On coarse cell-type classification it's a wash, both around ninety percent. On subtle state changes the gap opens — a two percent gain in classifying infection status, a twenty-four percent gain at identifying which gene was knocked down in a CRISPR interference screen, and a ten percent gain in area under the ROC curve for recovering the genes that actually moved under perturbation. Cleaner inputs, better model. That is the argument that agentic curation is not merely cheaper.

The honest limits: sixty-one thousand of a hundred and eleven thousand target experiments have been reprocessed, so this is a resource in progress, and it is ten-x Genomics and Illumina only. The cell type labels aren't expert annotations at all — a classifier trained on Tabula Sapiens assigned them. And the annotations the agent can't produce are the ones the archive never carried: which perturbation hit which cell, who the donor was.

The cost figure reframes the field. Their estimate for a human reading all two hundred and nine thousand records at a minute apiece is a hundred and forty-five days of continuous work. SRAgent did it for about seventeen thousand dollars in model calls, eighty seconds per dataset, and it keeps going — new submissions get picked up automatically. Agent and pipeline are both public.

The authors call it a blueprint, which is right, but I'd sharpen it. The lesson isn't that AI can curate data. It's that the archive has always been larger than the atlas, and what stood between them was never compute — it was the unglamorous work of reading what somebody typed into a submission form and deciding what it meant. That work just got affordable. Every field sitting on a repository with bad metadata should read this as a to-do item.
